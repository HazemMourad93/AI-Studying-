Example: how to TEST an AI Interviewer observation accurately

Question: “When would you choose a relational database over MongoDB?”

Source answer: “I prefer SQL for structured relations and transactions.”

AI observation: “Candidate has eight years of MongoDB administration experience.”

Verdict: FAIL — critical unsupported claim. The observation invents experience that was never demonstrated. A fluent sentence is not evidence.

  1. Choose job-related requirement and define the expected rubric.
  2. Build 10–20 synthetic, independently checked golden answers (include incomplete, Arabic and silence).
  3. Run the actual model and preserve question, answer, timestamps, model/prompt/rubric versions.
  4. Verify every observation claim against its source transcript span; mark supported or unsupported.
  5. Compute metrics, analyze false passes/rejects, rerun equivalent answer variants and document safety/bias failures.
  6. Approve a release only against pre-agreed quality thresholds with enough evidence; escalate high-risk unsupported claims for human review.

Minimal Python evaluation recipe

Start with CSV/Pandas + scikit-learn; then automate LLM semantic assessment using your Karthik KK DeepEval course. This code measures candidate-level classification, not observation factual grounding.

# candidate_evaluation.csv columns: candidate_id, expected_label, predicted_label
import pandas as pd
from sklearn.metrics import confusion_matrix, precision_score, recall_score, f1_score

df = pd.read_csv("candidate_evaluation.csv")
required = {"candidate_id", "expected_label", "predicted_label"}
assert required.issubset(df.columns)
assert not df[["expected_label", "predicted_label"]].isna().any().any()
labels = {"PASS", "REVIEW"}
assert set(df["expected_label"].str.upper()).issubset(labels)
assert set(df["predicted_label"].str.upper()).issubset(labels)

golden = df["expected_label"].str.upper().eq("PASS")
pred = df["predicted_label"].str.upper().eq("PASS")
tn, fp, fn, tp = confusion_matrix(golden, pred, labels=[False, True]).ravel()
print(f"TN={tn}, FP={fp}, FN={fn}, TP={tp}")
print("precision:", precision_score(golden, pred, zero_division=0))
print("recall:", recall_score(golden, pred, zero_division=0))
print("F1:", f1_score(golden, pred, zero_division=0))
# Set release PASS/FAIL only against an approved QA/Product threshold.
# A model can score well yet invent a critical hiring qualification:
# review unsupported observation claims independently!

Install: pip install pandas scikit-learn pytest. Run: python test_candidate_metrics.py after adapting the file contents. To measure observation factual grounding, add a separate expert-reviewed claim-level dataset and rubric-based evaluation.

Evidence checklist: requirement, risk level, consent-safe synthetic dataset version, independent oracle, model/version, prompt/rubric version, repeat count, sample size, metrics, exact failed examples, agreed thresholds and human-review decision. A missing threshold means NOT YET APPROVED, not PASS.

6. Your AI QA manifesto

1. Test membership in the saved question bank; random order is allowed
2. Reject invented questions and unconfigured follow-ups; test timers only when configured
3. Never require exact text from non-deterministic outputs
4. Use expert-reviewed scoring expectations
5. Repeat tests to assess variability
6. Test strong, weak and borderline candidate answers
7. Check fairness without assuming demographic differences imply ability
8. Test prompt injection and unsupported claims
9. Keep evaluation data version-controlled
10. Make release decisions from reproducible evidence
